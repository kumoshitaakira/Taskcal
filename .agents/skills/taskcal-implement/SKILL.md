# Taskcalの機能を実装する

## 契約を特定する

`AGENTS.md`の関係箇所を読み、現在のコードと、作業を規定する次の文書だけを確認する。

- ドメイン動作：`docs/rfc/RFC-009-domain-v04.md`
- CSV原本：`docs/rfc/RFC-010-csv-authority.md`
- 打診と承諾：`docs/rfc/RFC-011-outreach-and-state.md`
- 受入と開発：`docs/rfc/RFC-012-delivery-and-acceptance.md`
- 未決事項：`docs/OPEN-QUESTIONS.md`

振る舞いを固定する前に、関係する受入ケースと未決事項IDを示す。未決事項が実装を妨げ、ユーザー指定がない場合は、文書の初期推奨を変更可能なMVP既定値として使う。採用済みのプロダクト判断とはせず、実装上の仮定として記録する。

## 縦断機能を作る

入力から永続化した結果まで実演できる単位に絞る。次の責任を分ける。

- ドメイン規則と状態遷移
- アプリケーションの進行制御とtransaction境界
- CSV、OrcaRouter、メッセージングのadapter
- APIとUIの表示

認可、本人確認、候補適格性、時間計算、最新承諾の選択、月次上限、期限、予算、正式採用は決定的なコードで処理する。モデル出力は検証可能な構造化データと、許可した次行動だけに制限する。

状態変更には安定した操作ID、リクエストハッシュ、保存済み結果を使う。モデル処理より前に受信イベントを永続化する。正式採用の直前に版、未処理返信、停止状態、承諾を再検査する。結果照会または照合なしに、結果不明の外部作用を再実行しない。

## 振る舞いを検証する

変更した契約に絞ったテストを追加する。正常系に加え、関係する重複、古い入力、並行処理、停止、一部成功、結果不明のケースを確認する。該当する場合はA01〜A18へ紐づける。

決定的テストとOrcaRouterを使う実モデル評価を分ける。実呼出しでは事前に設定済み予算を検査し、実測・推定・取得不能を区別して記録する。

文書に記載されたformat、型検査、対象テストを実行する。実行した内容と未確認事項を正確に報告する。

## 記録を揃える

コマンドや環境要件を変えたら起動手順を更新する。実装が永続的な判断または外部から見える契約を変える場合は`taskcal-record-decision`を使い、完了前にADR/RFCを更新する。
