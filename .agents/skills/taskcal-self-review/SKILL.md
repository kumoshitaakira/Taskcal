# 完了報告の前に自己点検する

PR #4で受けた外部レビューの指摘を分類し、繰り返した失敗だけを手順にしている。
一般的なレビュー観点は`taskcal-review-change`にあるので重複させない。

機械的に検出できる項目は`npm run check:consistency`が見る。ここには**判断が要る
項目だけ**を書く。

## 1. 機械的検査を通す

```
npm run check:consistency
npm run format:check && npm run lint && npm run typecheck
npm test && npm run build
```

変更に**該当する**ものを実行する（`AGENTS.md`「品質と証拠」）。文書だけの変更で
`build`まで回す必要はない。失敗を残したまま次へ進まない。実行できなかったものは
報告に書く。

## 2. 変更した規則の「対になる側」を挙げる

片方に入れた規則を、もう片方に入れたか。実際に繰り返した型は次のとおり。

| 型 | 実例 |
|---|---|
| 送信側に入れて受信側に入れない | `requestHash`をモデル呼出しに入れて送信操作に入れない |
| 定義して呼ばない | `settle`、`validateEvidenceSpans`を作ってどこからも呼ばない |
| 一方向だけ分離した | DB点検をOrca設定から分離し、逆方向を残した |
| 兄弟ルールを見ない | マスクの電話番号を直し、URLとLINE表記を放置した |
| 必須にする項目を揃えない | `run_id`を必須にし`case_id`をoptionalのまま残した |

変更したファイルの同種の関数・型・ルールを`grep`で列挙し、1つずつ突き合わせる。
対になる規則を見つけたら、`scripts/check-consistency.ts`の`SYMMETRY_RULES`へ足す。

## 3. 落ちる場所を1つずつ数える

順序のある処理（予約・外部呼出し・保存・精算）で、各隙間で停止した場合を数える。

- 再実行が二重の外部作用にならないか
- 結果が確認できないとき、確定失敗と断定していないか
- 保存済みの結果を返す経路が、設定・上限・予算に依存していないか

## 4. 入力と計算結果の両方を検査したか

入力の値域だけ見て、計算結果の値域を見ていない箇所がないか。
実例：トークン数を非負整数として検査したが、単価との積が安全整数を超える経路を
残した。

## 5. 文字列変換は境界値の表で確かめる

変換規則を足したら、**全ルール×境界文字の表**を作る。1つの代表例では足りない。
勤務条件（時刻・日付・範囲表記）を壊していないことを必ず入れる。
実例：マスクで「後続の勤務条件を飲み込む」欠陥を、電話番号・URL・LINE表記で
4回作った。いずれも指摘された文字だけを足して、兄弟ルールを見ていなかった。

## 6. 文書・設定・テストの追随

値や名前を変えたら、それを説明している箇所を`grep`で洗う。
`.env.example`、`README.md`、`docs/`、各`README.md`、テストのfixture。

## 7. レビューエージェントへ委譲する

`src/`を変更した場合は既定で委譲する。自分の直後のコードを自分で読み返す形式は
弱い。PR #4では、委譲したレビューが外部レビューより先に欠陥を見つけた回があった。

`AGENTS.md`の「レビューエージェント」節のとおり、**独立して実行できる限定的な
レビューだけ**を委譲する。差分全体を毎回渡さない。

| 対象 | エージェント |
|---|---|
| ドメイン規則、契約、状態遷移、正式採用、冪等性、復旧、並行処理 | `taskcal-domain-reviewer` |
| MVP範囲、セキュリティ、費用、UX、実演証拠、受入 | `taskcal-delivery-reviewer` |

文書・設定だけの変更では省いてよい。省いた場合は報告にその旨を書く。
返ってきた指摘は主エージェントが判断し、根拠を確認してから反映する。

## 8. 指摘を受けたら検査を育てる

同種の指摘を受けたときは、修正だけで終えない。その分類が既存の機械的検査で
拾えなかった理由を調べ、検査を拡張する。
実例：文書乖離の検査は値と名前しか見ておらず、説明文の陳腐化を拾えずに2回再発
した。廃止表現の検査を足して収束した。

## 9. 報告する

実行した確認と、実行していない確認を分けて書く。委譲したか、省いたならなぜかを
書く。指摘がなかったことを「問題なし」と書かず、残るリスクと未確認の範囲を示す。
