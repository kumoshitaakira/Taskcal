# RFC-012：改訂版の開発・検証・移行計画

作成：2026-09-20／更新：2026-09-20／状態：ユーザー承認済みの分担方針、作業未実施
関連：[RFC-009](RFC-009-domain-v04.md)、[RFC-010](RFC-010-csv-authority.md)、[RFC-011](RFC-011-outreach-and-state.md)、[ADR-021](../adr/ADR-021-two-person-delivery.md)

## 1. 旧計画からの変更

RFC-005の2人・4日を維持する。Aはフロントエンドに強いフルスタック経験者、BはAPI・DB・アーキテクチャ周りの開発経験はあるが、全体として経験が浅い。単純なフロント／バック分業ではなく、Aがクリティカルパスと全体統合を持ち、Bが単独で完了できる決定的なバックエンド領域と検証を持つ。

CSV原本・正式版参照・同時対話が追加されたため、旧38人時を検証済み見積りとして流用しない。

1人1日6時間なら48人時という仮定は維持し、以下は40人時＋余裕8人時の初期見積りとする。A22人時＋余裕2、B18人時＋余裕6。Bの余裕は学習、レビュー修正、試験追加に使い、Aの未完了作業を無条件に移管する枠とはみなさない。実際の得意言語・稼働・環境をDay 1に確認して再見積りする。納期の保証ではない。

## 2. 着手前に必要な選択

Day 1の最初の90分で、Q01正式CSVの採用、Q02超過配置、Q03分断時間、Q04部分欠勤、Q05日跨ぎ、Q06月次集計、Q07通知完了、Q09自然文の対応範囲を固定する。全てを広く実装することが完成条件ではない。範囲外を明示して拒否する案も有効。

初期推奨は、アプリ内正式版への採用、各時間帯ちょうど1人、分断時間・部分欠勤・日跨ぎは範囲外、完了済みを含む予定勤務で月次上限を計算、正式採用・読戻し・必要通知受付までを業務完了、自然文は限定文型とし曖昧な場合は追加確認とする。これは着手会議で確定するための推奨であり、会議前に各Qを承認済みへ変更しない。

言語・DB・CSV列・認証の実装詳細は後続。旧TypeScript／Next.js／PostgreSQLは候補構成であり、v0.4の記録が新たに製品選定を確定したとは扱わない。

## 3. 役割と所有範囲

| 担当 | 主責任 | 所有する領域 | 相互確認 |
|---|---|---|---|
| A：フロント寄りフルスタック経験者 | 技術責任者・統合担当 | UI、API契約、案件状態機械、正式採用、OrcaRouter、web/worker/DB結合 | BのDB制約・版・例外処理を確認 |
| B：バックエンド経験あり・全体として経験浅め | ドメイン・データ・検証担当 | CSV、fixture、時間計算、候補選定、migration下書き、repository、受入試験 | Aの実装へ受入ケースから反例を作る |

Bを補助作業だけにせず、CSV取込、時間計算、候補選定、fixture、試験を独立した成果として所有させる。一方、本人の承諾から正式採用へ進む状態遷移、DB取引、競合・冪等性・結果照合、OrcaRouter実接続はAが最終責任を持つ。

### 3.1 コード所有の初期案

技術構成がTypeScript／Next.js候補から変わる場合も、責任境界は維持して実際のパスへ読み替える。

| パス | 主担当 | 内容 |
|---|---|---|
| `src/app/` | A | 店長画面、スタッフ画面、Route Handler |
| `src/application/` | A | use case、状態遷移、正式採用の進行制御 |
| `src/agent/`、`src/adapters/orca/` | A | OrcaRouter、返信解釈、action選択、費用記録 |
| `src/domain/interval/` | B | 時間区間、重複、充足計算 |
| `src/domain/selection/` | B | 候補評価、勤務計画の選定 |
| `src/adapters/csv/` | B | CSV正規化、安定ID、読戻し |
| `src/adapters/db/migrations/` | B作成・A承認 | schema、制約、index |
| `fixtures/`、`tests/` | B中心 | デモデータ、単体・統合・受入試験 |
| `src/contracts/` | 共同 | API、イベント、モデル出力schema |

`src/contracts/`はDay 1に共同で固定する。以後の変更は、変更者でない側の確認を必須とする。コード所有は排他的な編集権ではなく、設計・完了・説明の責任を示す。

### 3.3 共同作業ルール

- フロント全体／バック全体の長期ブランチを作らず、CSV取込、候補選定、案件進行、正式採用等の小さな機能単位で統合する。
- 毎日、昼と終了1時間前の2回を統合時刻にする。昼は型・interface、夕方は日別ゲートを実操作で確認する。
- 30分以上進まない場合は共有する。Aが全て引き取らず、入出力固定、最小例の提示、短時間のペア設計、任意範囲の対象外化のいずれかを選ぶ。
- 対象外化できるのは、UIの装飾、自然文入力の対応幅、比較回数、追加の入力形式・例外対応等に限る。本人確認・認証、適格性と時間制約、本人の明示的な承諾、正式採用の原子性、冪等性・結果照合・復旧、停止時の安全な動作、優先受入ケースは削減しない。
- 必須保証を期限内に実装・検証できない場合は未実装または未達として記録し、デモや進捗報告で完成扱いにしない。任意範囲を削減して、必須保証の実装と検証を優先する。
- 各作業はコード、関係するテスト、再現用fixture、未確認事項を揃えて完了とする。
- Aのレビュー待ちが半日を超えた場合、Bは新しい実装へ進まず、試験・fixture・文書・既存変更の小分けを優先する。

## 5. 必須受入ケース

| ID | 入力・障害 | 期待する結果 |
|---|---|---|
| A01 | R1からR2を正式採用し次案件を開始 | R2の追加勤務を参照する |
| A02 | CSV保存後・正式採用前に停止 | 未採用CSVを勤務として数えない |
| A03 | 正式採用直後に応答喪失 | 操作結果を照合し、同じ勤務を再作成しない |
| A04 | 同じ旧版に対する二つの正式採用 | 一方だけ成立。別キーでも二重採用しない |
| A05 | 更新準備中に本人の訂正を受信 | 正式採用前に保留・失効を検知 |
| A06 | 入力CSVの行を並べ替えて再読込 | 勤務IDと案件の参照を維持 |
| A07 | 元CSVを誤って読戻す | 反映確認失敗として完了にしない |
| A08 | 全割当の一部の保存・適用で失敗 | 全件未採用。一部だけを正式勤務にしない |
| A09 | 月内入力不足／完了済みへの状態変更 | 未取得を0扱いせず、選んだ月次算式で残枠を守る |
| A10 | 別営業日の勤務変更・日跨ぎ | 検査した範囲の変更を検知。非対応なら入力を拒否 |
| A11 | A確認不能、B・Cで成立 | Aだけを理由に全体終了しない |
| A12 | 旧メッセージのAI結果が遅れて返る | 最新承諾を古い結果で復活させない |
| A13 | 確定通知失敗／終了後の追加返信 | 勤務確定を保持し、追加割当を作らない |
| A14 | 読取専用接続からファイル出力 | 出力のみと元原本反映済みを区別 |
| A15 | 宛先変更／他人の返信／接続別の同じイベントID | 本人・宛先の同一性を検査し、接続単位で重複排除 |
| A16 | B18〜20、C19〜22 | Q02で決めた超過配置ルールに従う |
| A17 | 空きが分断／元勤務の一部だけ欠勤 | Q03/Q04で決めた処理または範囲外拒否 |
| A18 | 店長停止、予算・回数・期限到達 | 新規打診・正式採用を止め、既確定の事実を保持 |

これは試験仕様であり、実行済み結果ではない。特にA16の期待値は未決方針を選んでから固定する。

## 6. AIと費用の評価

旧RFC-008の固定fixture、全高性能／全軽量／切替比較、失敗込み費用、正しい引き継ぎと自律完了の分離は維持する。旧20ケースをそのまま未修正で使わず、順次打診、ボタン同意、DB単独確定を前提にした期待値を更新する。

20ケース×3構成＝60実行、任意の追加12実行という規模は計画候補。回数達成より必須受入を優先する。モデルに依存しない事故試験は決定的な入力で行い、実モデル試験は別にする。費用予算未設定のまま実呼出しを始めない。

主な実演は「全員への個別打診→辞退・部分可否→成立する選定→正式版CSV→再読込→結果通知」。一つの訂正または成否不明の復旧も示す。更新CSVを見せるだけで、正式採用や次回参照の証拠に代えない。

## 7. 事業モデルへの影響

RFC-006の価格・顧客・ROIは未検証仮説のまま。CSVの正式採用がデモ内で成立しても、実店舗の既存シフト管理へ導入できる証明ではない。将来、毎回CSVの手動出力・取込みが必要なら、その時間を店長の負担と導入原価へ含める。

全員打診は順次打診より通知が増える可能性があるため、メッセージ費とスタッフ負担の仮定を再測定する。価格2,980円・10案件の仮説を再承認された料金と扱わない。
