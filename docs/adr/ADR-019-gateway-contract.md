# ADR-019：外部連携は結果照会と保証範囲を含む契約にする

日付：2026-09-20／状態：Gateway分離は現行方針、結果型・能力の詳細は提案  
詳細：[RFC-010](../rfc/RFC-010-csv-authority.md)、[RFC-011](../rfc/RFC-011-outreach-and-state.md)

## 背景

CSV・SaaS、模擬メッセージ・LINEでは、入出力形式だけでなく更新の一括性、版検査、照会、配送の保証が異なる。共通interfaceだけで同じ保証にはならない。

## 記録する方針と補足案

ドメインから接続方式を分ける。ScheduleGatewayは更新内容を固定したコマンドを受け、結果・更新後参照・操作照会を返す契約を提案する。反映済み、一部反映、成否不明、出力のみを区別する。

SourceCapabilitiesには「版を読める」と「期待版を指定した更新ができる」の違いを持たせる。複数勤務の一括適用と結果照会も確認する。未対応の機能は、出力のみまたは停止へ落とし、同じ確定保証を主張しない。

MessagingGatewayは宛先の同一性、送信結果、受信検証、接続単位の重複排除を担う。連携設定の秘密値はドメイン・本文・ログへ出さない。

## 選択肢と帰結

各サービスへ直接依存すれば初期コードは少ないが、接続差が業務ロジックへ広がる。完全な汎用連携基盤は4日間には過大。CSV／テスト環境だけ実装し、将来側は契約と未対応範囲を残す。

## 検証・見直し

A07/A14/A15。具体的なSaaS・LINEを導入する時に最新仕様・本人紐づけ・権限・課金を検証し、専用RFCを追加する。現資料は本番接続の保証ではない。
