# ADR-017：案件・対話・更新・通知の状態を分離する

日付：2026-09-20／状態：レビュー反映の設計提案、完了境界はQ07未決  
詳細：[RFC-011](../rfc/RFC-011-outreach-and-state.md)

## 背景

同時打診で一人の追加確認を案件全体の状態にすると、他の承諾を処理できなくなる。更新済みでも読戻しや通知が失敗する場合があり、全てを技術エラーの終端へまとめると確定事実を失う。

## 提案する決定

AbsenceCaseは業務状態、Outreachは相手別対話、ScheduleUpdateは適用過程、送信管理はメッセージごとの配送状態を持つ。ProcessingEventはその証拠で、現在状態そのものの代用にはしない。

確定後の訂正は元の完了事実を保持した変更申告とし、調整を自動再開しない。成否不明は照合可能な状態として残す。店長停止と正式採用のどちらが先に成立したかを共通の順序で決める。

## 選択肢と帰結

一つの大きな状態enumは一見簡単だが、相手ごとの状態の組合せが増える。対象ごとに状態を分ければ、A確認中・B承諾済みを表せる。処理フロー図を残す場合は、永続する案件状態と別の図だと明記する。

## 未決・検証

必要通知の受付まで業務完了とする案を推奨。確定完了と通知完了を別にする案もQ07で選択可能。A11〜A13/A18で検証する。
