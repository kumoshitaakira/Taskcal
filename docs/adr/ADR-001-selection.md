# ADR-001：案05を採用し、欠勤リカバリーへ集中する

> 2026-09-20履歴注記：案05の採用は継続。MVPの詳細境界は[RFC-009](../rfc/RFC-009-domain-v04.md)と[未決事項](../OPEN-QUESTIONS.md)を優先します。以下は当時の判断記録です。

日付：2026-09-19  
状態：案05の選択はユーザー決定済み。下記のMVP境界は設計上の暫定決定。  
詳細：[RFC-001](../rfc/RFC-001-product.md)

## 背景

テーマは業務を自律化するAIエージェント。期間4日、2人、現場の専門家・協力先なし。ユーザーは案05で進める意思を示した。旧比較では案02も候補だったが、現在は再選定が目的ではない。

## 決定

飲食店の既存スタッフ内で、突発欠勤の打診・条件整理・再調整・勤務反映を進める案を採用する。4日間は架空1店舗、最大8スタッフ、1職種、同時1案件、最長4時間、必要人数1、同一営業日に限定する。食材発注、天候連動、採用、給与は対象外。

## 比較した選択肢

| 選択肢 | 判断 |
|---|---|
| 案02へ戻る | ユーザーの採用方針と異なるため選ばない |
| 案05の店舗業務全体を自動化 | 異なる業務・外部サービス・失敗条件が増え4日間の検証が薄くなる |
| 欠勤調整の閉じたループ | 返信による計画変更、同意、反映、失敗時停止を一連で示せるため採用 |

## 結果と不利益

説明と実演が一貫する。一方、実店舗の需要や労務上の適用条件は未検証。デモの成功を市場性の証明には使えない。候補人員に余力がないケースは引き継ぎで終わる。

## 検証・見直し

E01〜E06で業務価値の最小形を確認する。日跨ぎ・複数役割等が初期顧客の必須条件と判明したら、新RFCで範囲を再検討する。開発遅延だけを理由に案02へ自動的に切り替えない。
