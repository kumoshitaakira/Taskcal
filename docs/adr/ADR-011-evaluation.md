# ADR-011：失敗を含む固定ケースで業務完了と費用を比較する

> 2026-09-20継続注記：固定評価・失敗込み費用・禁止操作の優先は継続。現行方式の受入ケースと旧fixtureの移行は[RFC-012](../rfc/RFC-012-delivery-and-acceptance.md)に記録しました。

日付：2026-09-19／状態：評価方針の暫定決定、測定未実施  
詳細：[RFC-008](../rfc/RFC-008-evaluation.md)

## 背景

成功シナリオの録画や推論1回の単価だけでは、再計画・堅牢性・実際の費用を評価できない。正しく人へ戻すことと自律的に勤務を確定することを同じ成功率へ混ぜると誤解を招く。

## 決定

開発用6ケースと固定評価20ケースを分離する。境界・障害の追加12ケースを持つ。全高性能F、全軽量L、切替Rを同じ条件で20件ずつ実行し、時間・予算が許せば12回追加する。

正しい終了、自律完了、禁止操作、店長介入、費用、時間、通知負担を分ける。失敗呼出しも費用に含め、UNKNOWNを0円にしない。必須事故試験に違反すれば平均点が高くても不合格。

## 選択肢

成功例だけの実演は説明しやすいが保証範囲を示せない。多数の自動生成例は量を増やせるが期待値もAI任せになりやすい。小さな固定ケースと独立した不変条件で検証する方式を採用する。

## 結果と不利益

60〜72実行でも市場や任意入力への一般化には足りない。予算・時間を消費するので、API実評価と決定的な業務試験を分ける。評価後の修正は再評価として記録する。

## 検証・見直し

最終版にcommit・fixture・prompt・Router版と結果を紐づける。実店舗で得た同意済み・匿名化済みの新しい失敗例を追加する際は、既存評価との比較範囲を残す。ハッカソン結果を実店舗の削減効果と置き換えない。
