# ADR-008：不要な個人情報を収集せず、本人・店舗・実行範囲をサーバーで検査する

> 2026-09-20継続注記：最小収集・認可・本人確認の原則は継続。宛先版と受信順の補足は[RFC-011](../rfc/RFC-011-outreach-and-state.md)を参照してください。

日付：2026-09-19／状態：設計上の暫定決定、本番適用は追加確認が必要  
詳細：[RFC-007](../rfc/RFC-007-security-operations.md)

## 背景

従業員の連絡先、健康・家庭事情、勤務可能時間は、欠勤調整に必要な情報と不要な情報が混在する。AIが外部入力を読むこと、店長が雇用上の力を持つことが、通常のチャットより慎重な設計を必要にする。

## 決定

欠勤理由の欄を設けず、辞退理由を要求しない。モデルには案件内匿名IDと必要条件のみを渡す。自由文をマスクしても完全匿名化と称さない。辞退履歴を候補の減点に使わない。

認証からtenant/store/actorを決定し、全APIで対象資源の所属・本人を照合する。キーはサーバー保管、任意SQL・URL・宛先をモデルへ提供しない。デモ役切替はローカル限定。実データ導入前に利用目的、再委託、地域、保持、削除、実認証を整える。

## 選択肢

全履歴をモデルへ渡せば文脈が増えるが不要な開示と誤利用が増える。正規表現マスクだけで匿名化済みとする案は見逃しを扱えない。最小収集・認可・限定ツールを重ねる設計を採用する。

## 結果と不利益

複雑な個別事情への最適化をあえて行わない。問い合わせに答えるための保持と本人の削除要求には調整が必要。法定・契約上の記録を一律短期削除しない。

## 検証・見直し

E13/E19/E20、B07/B08/B09を検証する。公開・実スタッフ・複数店舗への拡張時には脅威分析を更新。OrcaRouterのログ地域と上流推論地域を混同しない。
