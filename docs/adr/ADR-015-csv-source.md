# ADR-015：MVPの勤務原本をCSVにし、Gatewayで接続差を分ける

日付：2026-09-20／状態：v0.4に明記された現行設計方針、未実装  
詳細：[RFC-010](../rfc/RFC-010-csv-authority.md)／関連：[ADR-016](ADR-016-csv-adoption.md)、[ADR-019](ADR-019-gateway-contract.md)

## 背景

v0.4は内部DBだけで完結する勤務表から、CSVを原本として取り込み、更新版を別ファイルに出す方式へ変更した。将来のSaaSと固有形式を分離したい。

## 決定として記録する方針

MVPの勤務入出力はCSV、連絡は模擬受信箱。ScheduleGatewayとMessagingGatewayを境界にする。SaaS・LINEの実接続は将来対象。元CSVを上書きせず、変更前後を残す。秘密情報はconnectionIdから解決する設定へ分離する。

## 選択肢と理由

内部DBだけを勤務正本にする案は原子的更新を実装しやすい。一方CSVは入出力を目視しやすく外部原本の扱いを示せる。今回の文書はCSV方式を選んだ。CSVなら自動的に開発が簡単になるという意味ではない。

## 帰結

CSVの勤務ID、正規化、正式参照、読戻し、ファイルと内部状態の復旧が必要。内部versionとsourceRevisionは別。旧DB単独の確定保証をそのまま外部更新へ移せない。

## 未決・検証

出力版を正式採用するか変更案として渡すかはQ01、ADR-016に分離する。CSV列と保存製品は未決。A01〜A08で往復と再開を確認する。
