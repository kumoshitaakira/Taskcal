## 2. ライブ実演の手順（3分）

主実演は RFC-012 §6「全員への個別打診→辞退・部分可否→成立する選定→正式版CSV→再読込→結果通知」。

1. workerを止めた状態で `npm run reset:dev` → `npm run dev` / `npm run worker` を起動（事前・リポジトリのルートで）。`/api/health` が正常。
2. `/manager`：9/25 18:00〜20:00（架空 えいた）の欠勤を登録。回答期限は既定値。
3. 打診を開始。**3件**（あかり・いつき・うみ）。適格性で外れた相手が居れば処理記録（DB）に理由が残ることを口頭で補足する（画面には出ない）。
4. `/staff`：あかり「大丈夫です」、いつき「19時からなら行けます」、うみ「今回は難しいです」。
5. `/manager`：workerの解釈を待つ。上限はOrcaRouterのタイムアウト（`ORCA_TIMEOUT_MS`。既定20秒、手元の設定は60秒）で、2026-09-22の実測は1件10〜30秒。実演では**先に返信して待ち時間を吸収**。
   あかりが「承諾あり・選定可」、いつきが追加確認または部分承諾、うみが辞退。
6. 「正式採用へ進む」。あかり1人（18〜20時）が唯一の合法な計画として選ばれ（いつき単独は隙間、あかり＋いつきは重複）、「1件の代替勤務を正式採用しました。
   読戻しも一致しています」。勤務表更新に成果物 `revisions/<hash>`（正式版）が出る。
7. `var/schedule/<接続>/revisions/<hash>/schedule.csv` を開き、`ABSENT` と由来つきの代替勤務を見せる。
8. workerが通知を送り、案件が**完了**。`/staff` で確定・非選定・募集終了の通知を見せる。

障害の実演（1本）：手順6の直後に「調整を停止する」は出ないので、代わりに**手順3の直後に停止**し、
募集終了通知と承諾の失効、停止が取り消せないことを見せる（A18の店長停止・本番経路）。

ライブで詰まった場合は、事前に撮った録画を再生し、**録画であることを明記する**（RFC-012 §4）。

## 3. 完成として言うこと・言わないこと

| 言える | 言わない |
|---|---|
| 欠勤登録から正式採用・通知・完了まで、本番経路で1店舗・1案件が通る | 実店舗の勤務表サービスへ反映できる |
| 承諾は本人の返信だけを根拠に、決定的検査を通したものだけ | 返信解釈の精度を評価した（RFC-008の固定fixture評価は未実施） |
| 打診時と採用直前に在籍・職種・重複・月次上限を検査する | 本人の可能時間を検査する（可能時間表が無い） |
| 成否不明は再実行せず照合する。未採用と断定しない | 全ての障害から自動で復旧する（A18の上限側、FAILED通知の再送、人が引き取る操作は未実装） |
| CSVは管理版として不変に保存し、正式版はDBの参照が決める | CSVの外部取込み（アップロード）ができる |
