# 設計記録の変更履歴

## 2026-09-20：Taskcalへの命名とリポジトリ移管

- ユーザー指定のサービス名Taskcalを採用し、ADR-020を追加。
- ルートREADMEをサービス概要、docs/READMEを設計索引とした。
- ADR・RFC・提供資料・レビュー・企画比較・スライド・配布ZIPをTaskcalリポジトリへ移管。
- 現行の案内と相対リンクを更新し、添付原文・過去の判断・バイナリ成果物を保持。
- 未決事項の採用状態は変更しない。commit・push・アプリ実装はこの移管に含めない。

## 2026-09-20：v0.4と一連のレビューを統合

- RFC-009〜012を追加：ドメイン、CSV正式採用、同時対話・状態、改訂開発・検証。
- ADR-012〜019を追加：現行方針、レビュー提案、未決判断を区別して記録。
- 未決事項Q01〜Q10を一箇所に集約。
- 受入ケースA01〜A18を追加。試験結果ではない。
- 元添付4文書とレビュー4文書をreferencesへ保存。元添付の本文は変更しない。
- 初期のRFC-001〜008／ADR-001〜011は削除せず、適用範囲・後継への注記を追加。
- 以前の資料一式は別の2026-09-19版ZIPとして保管。

## 新旧の判断対応

| 以前の提案 | 現行の記録 | 関連 |
|---|---|---|
| 一人ずつ順次打診 | 全適格者へ個別同時打診 | ADR-013／RFC-011 |
| 全件構造化ボタンで同意 | 明確な自然文を承諾に使用。成立・保留条件を補う | ADR-014／RFC-011 |
| 通常／代替勤務等の個別モデル | Schedule集約・共通ShiftAssignment、選定スナップショット | ADR-012／RFC-009 |
| 内部DBの勤務が正本 | 外部CSVが原本、内部は共通モデル | ADR-015／RFC-010 |
| DB更新で勤務確定 | 出力作成と正式採用を分ける提案。採用方式は未決 | ADR-016／Q01 |
| 1つの案件状態に処理段階を列挙 | 案件・相手別対話・更新・通知の分離提案 | ADR-017／RFC-011 |
| 余剰配置禁止・単一区間等の旧既定 | 新版で選択未確定のため明示的に再決定 | ADR-018／Q02〜Q06 |
| 18テーブル等の技術ベースライン | 技術候補として残す。v0.4に合わせた物理設計は未実施 | RFC-003／RFC-012 |
| 旧38人時 | 改訂40人時の仮見積り＋余裕8。実稼働確認前 | RFC-012 |
| 旧20ケース・比較60〜72実行 | 比較方針は継続。新契約に合わせ期待値を変更 | RFC-008／RFC-012 |

## 変更しない方針

案05、2人・4日、架空データ・模擬チャネル、OrcaRouter利用、未承諾の割当禁止、本人の時間の無断短縮禁止、失敗を成功と表示しない、必要な費用・検査証拠、価格と現場効果が未検証であること。

## 記録のステータス

「ユーザー確認済み」は会話で明示された条件。「現行設計方針」は提供されたv0.4に書かれた方針。「提案」はレビューによる具体化。「未決」は複数の選択肢が残るもの。どの状態も実装・検証済みとは同義ではない。
