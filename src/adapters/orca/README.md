# src/adapters/orca

OrcaRouter経由の推論。担当A（RFC-012 §3.1）。

**2026-09-22時点：接続先とモデルを設定した。実呼出しの検証状況はルートREADMEの
「現時点で動かないもの」を参照する。** 設定が欠けていれば既定で
`UnconfiguredModelGateway` を使い、模擬結果は返さない。

| 設定 | 値 |
|---|---|
| `ORCA_BASE_URL` | `https://api.orcarouter.ai/v1`（OpenAI互換） |
| `ORCA_MODEL` | `orcarouter/free`（無料モデルへ振るRouter） |

`ORCA_MODEL` に**既定値を置かない**。どれを呼ぶか決まっていなければ、その単価も
決まっておらず、保守的な予約額を作れない（RFC-004 §7）。未設定なら実呼出しを開始しない。

`orcarouter/` で始まるIDは**Routerが実モデルを決める別名**で、記録上の「モデルを選んだ
主体」は `ROUTER` になる（`isRouterAlias`）。具体的なモデル名を指したときだけ
`APPLICATION` になる。指定した文字列をそのまま実使用モデルの証拠にしない——実使用は
応答の `model` からしか分からず、取れなければ `UNKNOWN` のままにする（RFC-004 §8）。

**無料モデル構成では金額上限が歯止めになっていない。** 実費は $0 で、単価には正の
最小値（名目値）を置いている。実際に効くのは `case_call_limit`（回数）だけ。有料モデルへ
切り替えるなら、単価と金額上限を決め直すこと（`docs/OPEN-QUESTIONS.md` Q10）。

- 実呼出しはサーバーからのみ行う。キーをブラウザ・モバイルクライアントへ渡さない（AGENTS.md）。
- 金額は**USDの整数micro単位**で記録する（RFC-004 §7）。円換算は表示時に、換算日時と
  レートを添えて行う。内部で円を持たない。
- `case_spend_limit` / `run_spend_limit` / 候補モデルの単価が未設定なら有料呼出しを
  開始しない（RFC-004 §7、ADR-007、Q10）。`case_call_limit` が未設定の場合は
  Q10で暫定確定した24を既定にする（`DEFAULT_CASE_CALL_LIMIT`）。ADR-007の10call／案件は
  順次打診を前提にした値のため置き換えた。24は**検証前の上限候補**であり、十分な回数だ
  という保証ではない。
- 予約は `request_id` で冪等にし、`request_hash` を台帳へ保存して再予約時に照合する。
  同じIDで内容が異なる要求は `OPERATION_CONFLICT` で拒否する（D07）。
  `request_id` は**呼出し元が永続化**し、adapter側で採番しない。
- **保存済み結果の照会を最初に行う。** 再生は外部呼出しを要さないため、接続設定・
  入力上限・単価・予算のどれにも依存させない。後ろに置くと、`ORCA_MAX_REPLY_CHARS`
  を下げただけで確定済みの解釈が復旧できなくなる。
- **`ALREADY_RESERVED` は「呼出してよい」ではない。** 予約が一重でも、そこから
  `fetch` すると有料推論は二重に走る。保存済み結果（`ModelCallStore`）を返すか、
  結果が確認できなければ `RECONCILE_REQUIRED` として人の対応へ回す。再送しない。
- モデルへは、元打診に加えて**現在の承諾と確定状態**を渡す（Q09）。訂正・撤回は
  既存の回答を指すため、これが無いと解釈できない。氏名・連絡先は渡さない。
- 送信前に連絡先をマスクする（`mask.ts`、RFC-004 §5）。**過剰マスクは検知漏れより
  悪い。** 勤務時間帯の範囲表記（`1700-2200`）を電話番号として消すと、解釈そのものが
  成立しない。電話番号は数字の合計桁数（国内10〜11桁）で絞り、URLは日本語の
  句読点・括弧でも終端させる。**ルールを足したら、勤務条件が直後に続く例を
  必ずテストへ足すこと**（電話番号・URL・LINE表記で同じ欠陥を4回作った）。
  URLは**終端文字を並べるのではなく、許す文字を列挙する**方式にした。
  「この記号でも終端する」を都度足す方式では、日本語句読点・ASCIIカンマ・
  ASCII閉じ括弧と3回追加することになったため。
  アカウントIDは**英字を1文字以上要求する**。`ID` も区切りも省略できる形にすると、
  `LINE 18-22で勤務できます` の `18-22` をIDとして飲み込む。数字だけのIDは
  取りこぼすが、勤務条件を壊すより取りこぼす側へ倒す。
- `evidenceSpans` の座標系は**マスク後の本文**。原文へそのまま当てない。
  `InterpretReplyResponse.maskedReplyText` と `StoredModelCall.maskedReplyText` を
  組で扱い、永続化の直前に `validateEvidenceSpans` で本文長と突き合わせる。
  `UNCLEAR` 以外の意思には、長さのある根拠を1つ以上要求する。根拠の無い `ACCEPT` を
  採用解釈として保存すると、後から判断の理由を説明できない（D03）。
- `isConfigured() === false` でも `interpretReply` は成功し得る（保存済み結果の再生）。
  「false なら呼んでも無駄」と判断して縮退しない。
- RFC-004 §6の修復・昇格（最大1回）は未実装。実装するときは `step` と `attempt` を
  含めて `requestId` を採番する。同じIDでは `ALREADY_RESERVED` になる。
- `cost_kind` が `MEASURED` になる経路はまだ無い。単価が未確認のため、実測トークンが
  取れても `ESTIMATED` 止まり。
- 実使用モデル・トークン・費用は、実測／推定／取得不能を区別して記録する（`usage.ts`）。
- タイムアウト・応答喪失は `UnknownOutcomeError`。費用0にも確定失敗にもしない。
  `InvalidModelOutputError` と併せて `TaskcalError` を継承する。呼出し元が
  `instanceof TaskcalError` で意味のある失敗を拾い、案件を止めずに保留へ回せるようにする
  （素の Error だと呼出し元を素通りし、同じ受信を選び続けて後続の返信が止まる）。
  課金不明は `UNKNOWN_CHARGE` とし、**予約を残す**（RFC-004 §7）。
- **どの終了経路でも `settle` を呼ぶ。** 成功・schema不一致・結果不明のいずれでも
  予約を予約のまま残さない。schema不一致でも呼出しは成立して課金されている。
- **schema不一致も結果不明も、確定した記録として保存する**
  （`outcome: "SCHEMA_INVALID"` / `"UNKNOWN"`）。保存しないと、再起動後の再試行で
  誤分類し、モデル・prompt/schema版・routing source・latency が例外オブジェクトと
  ともに失われる（RFC-004 §8）。結果不明は**例外を投げる前に**永続化する。
  再試行では同じ結果を決定的に返す。
- **再生時に精算をやり直す。** 結果を保存した直後、精算の前に停止すると、予約が
  残り続けて後続の呼出しを誤って上限で止める。`settle` は `requestId` で冪等。
- **固定額を予約しない**（`estimate.ts`）。入力長・出力上限・候補モデルの最大単価から
  要求ごとに見積もる。入力長の上限を超える返信は呼出さずに拒否する。
  単価が未設定なら有料呼出しを開始しない。
  トークン数の上限は**UTF-8のbyte長**で見積もる。Routerが候補モデルを選ぶ構成では
  tokenizerを特定できず、byte fallbackでは1文字が3〜4トークンになり得るため、
  文字数基準では上限にならない。
- モデルは返信解釈と限定された次行動の提案だけを行う。承諾成立はコードで検査する。

`orca-client.ts` の要求・応答形式はOpenAI互換を仮定した**下書き**であり、接続確認前の
推測を含む。接続情報が確定したら実応答に合わせて修正する。
