# src/adapters/orca

OrcaRouter経由の推論。担当A（RFC-012 §3.1）。

**2026-09-21時点：実呼出しは未実施・未検証。** APIキー、接続先、利用可能モデル、
単価がいずれも未取得のため、既定では `UnconfiguredModelGateway` を使う。

- 実呼出しはサーバーからのみ行う。キーをブラウザ・モバイルクライアントへ渡さない（AGENTS.md）。
- 金額は**USDの整数micro単位**で記録する（RFC-004 §7）。円換算は表示時に、換算日時と
  レートを添えて行う。内部で円を持たない。
- `case_spend_limit` / `run_spend_limit` / 候補モデルの単価が未設定なら有料呼出しを
  開始しない（RFC-004 §7、ADR-007、Q10）。`case_call_limit` が未設定の場合は
  Q10で暫定確定した24を既定にする（`DEFAULT_CASE_CALL_LIMIT`）。ADR-007の10call／案件は
  順次打診を前提にした値のため置き換えた。24は**検証前の上限候補**であり、十分な回数だ
  という保証ではない。
- 予約は `request_id` で冪等にし、`request_hash` を台帳へ保存して再予約時に照合する。
  同じIDで内容が異なる要求は `OPERATION_CONFLICT` で拒否する（D07）。
  `request_id` は**呼出し元が永続化**し、adapter側で採番しない。
- **`ALREADY_RESERVED` は「呼出してよい」ではない。** 予約が一重でも、そこから
  `fetch` すると有料推論は二重に走る。保存済み結果（`ModelCallStore`）を返すか、
  結果が確認できなければ `RECONCILE_REQUIRED` として人の対応へ回す。再送しない。
- モデルへは、元打診に加えて**現在の承諾と確定状態**を渡す（Q09）。訂正・撤回は
  既存の回答を指すため、これが無いと解釈できない。氏名・連絡先は渡さない。
- 実使用モデル・トークン・費用は、実測／推定／取得不能を区別して記録する（`usage.ts`）。
- タイムアウト・応答喪失は `UnknownOutcomeError`。費用0にも確定失敗にもしない。
  課金不明は `UNKNOWN_CHARGE` とし、**予約を残す**（RFC-004 §7）。
- **どの終了経路でも `settle` を呼ぶ。** 成功・schema不一致・結果不明のいずれでも
  予約を予約のまま残さない。schema不一致でも呼出しは成立して課金されている。
- **schema不一致も結果不明も、確定した記録として保存する**
  （`outcome: "SCHEMA_INVALID"` / `"UNKNOWN"`）。保存しないと、再起動後の再試行で
  誤分類し、モデル・prompt/schema版・routing source・latency が例外オブジェクトと
  ともに失われる（RFC-004 §8）。結果不明は**例外を投げる前に**永続化する。
  再試行では同じ結果を決定的に返す。
- **再生時に精算をやり直す。** 結果を保存した直後、精算の前に停止すると、予約が
  残り続けて後続の呼出しを誤って上限で止める。`settle` は `requestId` で冪等。
- **固定額を予約しない**（`estimate.ts`）。入力長・出力上限・候補モデルの最大単価から
  要求ごとに見積もる。入力長の上限を超える返信は呼出さずに拒否する。
  単価が未設定なら有料呼出しを開始しない。
  トークン数の上限は**UTF-8のbyte長**で見積もる。Routerが候補モデルを選ぶ構成では
  tokenizerを特定できず、byte fallbackでは1文字が3〜4トークンになり得るため、
  文字数基準では上限にならない。
- モデルは返信解釈と限定された次行動の提案だけを行う。承諾成立はコードで検査する。

`orca-client.ts` の要求・応答形式はOpenAI互換を仮定した**下書き**であり、接続確認前の
推測を含む。接続情報が確定したら実応答に合わせて修正する。
